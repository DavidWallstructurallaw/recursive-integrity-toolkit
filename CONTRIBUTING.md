# Contributing

Recursive Integrity Toolkit is a theory-led reference implementation. Contributions must preserve the approved specifications and phase boundaries.

## Before contributing

- Read `PROJECT_INSTRUCTIONS.md`.
- Identify relevant `TM-*`, `T*`, `PR-*`, `F-*`, and `UD-*` identifiers.
- Do not upload private training data, secrets, private paths, or confidential provenance.
- Use small synthetic fixtures.

## Pull requests

A behavior-changing pull request must state:

```text
Change class:
Trace IDs:
Theory Map IDs:
Product Rule IDs:
Formula IDs:
Decision IDs:
Public fields changed:
Tests changed:
Evidence classes changed:
Limitations changed:
Licensing impact:
Security impact:
```

## Phase rule

Phase 1 accepts repository-scaffold work only. Analytical implementation belongs to later approved phases.

## Licensing

By contributing, you agree that your contribution may be distributed under the license applicable to the target file or asset class.
