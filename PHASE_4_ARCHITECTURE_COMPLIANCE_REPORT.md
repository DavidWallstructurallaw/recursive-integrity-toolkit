# Phase 4 architecture compliance report

Status: candidate review in progress; final verification pending.
Starting commit: `9142b344bfc2dc2b33dbc696159f07bbc81b223a`.

## Product and scientific boundaries

Phase 4 composes existing mathematical results into explicit evidence-aware
reports and a local CLI. Observed facts, derived quantities and unavailable
conclusions retain distinct meanings. Missing provenance is not converted to
known origin or ancestry, and no universal quality, risk or collapse score is
introduced. The Phase 3 numerical oracles and schema semantics remain frozen.

The shipped report has stable JSON and Markdown forms. Comparison requires
explicit version-order and state-semantics context. Privacy redaction preserves
analytical values while suppressing protected report details. Local-only and
safe-publication boundaries remain covered by direct product tests. Lineage,
ancestry, simulations, embeddings and HTML remain outside this phase.

Step 11 changes only the package version literal in runtime source. The other
39 runtime modules, all schemas, seven package resources and literal golden
fixtures retain accepted Step 10 bytes. Current version expectations adapt
explicitly; actual output still has to identify the exact current version.

## Verification complexity

Canonical regression protects current behavior. Candidate/release verification
covers supported environments, package boundaries, examples, reproducibility
and actual performance. Git and archived receipts preserve superseded source
forms and historical evidence. Existing migration machinery is retained where
needed for accepted historical behavior; no successor chain or new registry is
added during Step 11.

Existing historical package tests use their already available accepted snapshot.
Current direct mutation rejection remains active. Complete candidate suites
execute once per required profile, and the build role consumes the same run's
core and Parquet evidence. Administrative acceptance edits do not automatically
repeat the full environment matrix when executable/authoritative bytes are
unchanged. These choices implement the user's verification governance policy.

The approved Step 10 repair avoids repeated full warning identity scopes and
repeated duplicate-group scope-set construction, preserving warning counts,
locations, encounter order and calculations. Its bounded mutation checks killed
three realistic defects. No general mutation framework was added.

## Review roles and limitations

Assistant agents perform implementation/control review, workflow/package review,
public documentation review and independent version/scientific/privacy review.
These are AI-assisted reviews. No human signature or external scientific review
is claimed. Actual findings and resolutions will be recorded in final evidence.

Initial independent review confirmed the Hero values, explicit unavailable
states, input-only validation, deferred lineage/simulation execution and
documented privacy/linkability limits. It identified current-version assertions
and a historical package test that otherwise depended on the moving checkout.
Explicit current-version expectations and the existing historical snapshot
resolved those issues; frozen oracle bytes and normalizer bytes were verified
unchanged. Workflow review confirmed that complete suites remain in all nine
required profiles, with build evidence reused from the same candidate run.

The measured 100k report remains large and memory intensive; the Step 10 result
does not establish an all-hardware SLA. Final platform outcomes remain pending.
Completion, publication authority and permission for Phase 5 are separate
decisions. This report grants none of them.
